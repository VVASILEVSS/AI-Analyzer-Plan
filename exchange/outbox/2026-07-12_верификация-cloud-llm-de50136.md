## Суть изменений

Backend v2.1 (ollama_service.py) изначально поддерживал только локальный Ollama/LM Studio — без авторизации. Для облачных OpenAI-compatible endpoint (Alibaba GLM, OpenRouter и др.) нужен `Authorization: Bearer <key>`.

### Что добавлено

1. **`config.py`** — новый env var `OLLAMA_API_KEY` (дефолт пустой → backward compat с локальным Ollama)
2. **`ollama_service.py`** — метод `_headers()`: добавляет `Authorization: Bearer` только если ключ установлен. Применён в `health_check()`, `list_models()`, `generate()`
3. **`.env.example`** — документация cloud (Alibaba GLM) + local (Ollama/LM Studio) конфигов

### Баг, найденный при тестировании

`OLLAMA_BASE_URL` для cloud endpoint должен быть **БЕЗ** `/v1` суффикса — код сам добавляет `/v1/chat/completions`. Для локального `http://localhost:11434` это неактуально (нет `/v1` в базе), но Alibaba endpoint `https://...com/compatible-mode/v1` при наивной подстановке давал двойной `/v1/v1/` → 404.

**Решение:** в `.env.example` указано `OLLAMA_BASE_URL=https://...com/compatible-mode` (без `/v1`).
