# Локальная модель под AI Analyzer v2.1 — анализ железа и рекомендации

**Дата:** 2026-07-12
**Автор:** Hermes Agent (glm-5.2-fast-preview)
**Кому:** Super Z
**Тема:** Выбор локальной LLM под фактическое железо (GTX 1650 Ti, 4 GB VRAM)

---

## ⚠️ Критическое расхождение с планом R2

План R2 (Этап 2, Консенсус) предполагает **12 GB VRAM** и пишет:
> «Одна GPU 12 GB. Нельзя держать 3 модели одновременно (Qwen 7B = 5GB + GLM-4 9B = 8GB = 13GB > 12GB). Model Router управляет загрузкой/выгрузкой.»

**Фактическое железо: 4 GB VRAM.** Это в 3 раза меньше. Консенсус 3 моделей физически невозможен. Qwen2.5-VL 7B (5 GB) не влезет без агрессивной квантизации. Раздел «Консенсус» плана R2 требует ревизии.

---

## 🔧 Фактическое железо (из WMI + nvidia-smi)

| Компонент | Значение |
|-----------|----------|
| **CPU** | Intel Core i5-10300H @ 2.50GHz, 4 ядра / 8 потоков |
| **RAM** | 16 GB (17008988160 байт ≈ 15.8 GB) |
| **GPU** | NVIDIA GeForce GTX 1650 Ti |
| **VRAM** | **4096 MiB (4 GB)** — занято 812 MiB, свободно ~3.1 GB |
| **Драйвер** | 610.62, CUDA 13.3 |
| **Диск C:** | 445 GB, свободно 168 GB |
| **Диск D:** | 931 GB, свободно 430 GB |
| **TDP** | 50W (мобильный чип, тепловые лимиты) |

**Примечания:**
- GTX 1650 Ti — мобильный GPU архитектуры Turing (TU117), 1024 CUDA ядер, Compute Capability 7.5
- 4 GB VRAM — жёсткий лимит, Windows + драйвер резервируют ~800 MB, **доступно ~3.1 GB**
- TDP 50W — тепловой потолок ниже десктопных карт, возможен throttle при длительной инференции

## 📊 Модели, которые влезают в 4 GB VRAM

Текущая модель проекта — **Qwen2.5-VL 7B Instruct** (LM Studio, endpoint localhost:1234). При Q4_K_M она занимает ~4.5 GB — **не помещается** в 4 GB VRAM целиком, частично оффлодится в RAM. Это объясняет медленный ответ.

### Рекомендация №1 (замена основной модели) — Qwen2.5 3B Instruct

| Параметр | Значение |
|----------|----------|
| Размер | 3.0B параметров |
| Q4_K_M GGUF | ~1.9 GB |
| Q5_K_M GGUF | ~2.2 GB |
| Q8_0 GGUF | ~3.1 GB |
| VRAM при Q4_K_M | ~2.2 GB (помещается полностью) |
| Контекст | до 32K (можно ужать до 8K) |
| Скорость | быстрый, годен для real-time сигналов |
| Пригодность | хорошая для JSON-сигналов и базового анализа |
| Источник | Ollama: `ollama pull qwen2.5:3b-instruct-q4_K_M` |

**Это лучший выбор под железо.** Влезает в VRAM целиком с запасом, быстрый, поддерживает JSON-structured output.

### Рекомендация №2 (если хочется качества) — Qwen2.5 7B Instruct (Q3_K_M или Q4_0)

| Параметр | Значение |
|----------|----------|
| Q3_K_M GGUF | ~3.1 GB (влезает впритык, 90% слоёв в VRAM) |
| Q4_0 GGUF | ~4.1 GB (только ~60% слоёв в VRAM, 40% в RAM) |
| VRAM при Q3_K_M | ~3.2 GB + оффлоад в RAM |
| Скорость | медленнее, но качество выше 3B |
| Пригодность | компромисс качество/скорость, но тепловой риск |
| Источник | Ollama: `ollama pull qwen2.5:7b-instruct-q3_K_M` |

⚠️ Текущая модель проекта — **Qwen2.5-VL 7B** (vision-language). Это тяжелее обычной 7B. Если vision не нужен (а для сигналов он, скорее всего, не нужен — биржа отдаёт JSON/числа), лучше заменить на text-only 7B или 3B.

### Рекомендация №3 (микс для Model Router) — Llama 3.2 1B / 3B

| Параметр | Значение |
|----------|----------|
| Llama 3.2 3B Instruct Q4_K_M | ~2.0 GB, влезает целиком |
| Llama 3.2 1B Instruct Q8_0 | ~1.3 GB, влезает с огромным запасом |
| Пригодность | fast-tier для Model Router (план R2 Этап 2) |
| Источник | Ollama: `ollama pull llama3.2:3b` / `ollama pull llama3.2:1b` |

Model Router может грузить 1B/3B для простых сигналов и 7B для expert mode — но **не одновременно** (памяти не хватит). Через `ollama ps` можно подгружать/выгружать.

### Рекомендация №4 (если нужен reasoning) — DeepSeek-R1 Distill Qwen 1.5B

| Параметр | Значение |
|----------|----------|
| Q4_K_M GGUF | ~1.1 GB |
| VRAM | ~1.5 GB (полностью в VRAM) |
| Особенность | reasoning-модель, пишет `<think>...` перед ответом |
| Пригодность | для сложных multi-step сигналов (expert mode) |
| Источник | Ollama: `ollama pull deepseek-r1:1.5b` |

## 🎯 Конкретный стек под железо

### Базовая конфигурация (рекомендую):
```
# Основная (standard mode)
qwen2.5:3b-instruct-q4_K_M         (~2.2 GB VRAM, быстро)

# Fast-tier (если Model Router реализован)
llama3.2:1b                        (~1.3 GB VRAM, мгновенно)
```

### Если важнее качество (медленнее):
```
# Основная
qwen2.5:7b-instruct-q3_K_M         (~3.2 GB VRAM, оффлоад в RAM)

# Не загружать одновременно с другой моделью!
```

### Чего НЕЛЬЗЯ:
- ❌ Qwen2.5-VL 7B (vision-language, тяжёлая, частичный оффлоад в RAM сейчас)
- ❌ GLM-4 9B Q4_K_M (~8 GB) — не поместится даже в RAM-оффлоаде приемлемо
- ❌ DeepSeek-R1 8B (~5 GB Q4) — частичный оффлоад, очень медленно
- ❌ Консенсус 3 моделей одновременно (план R2 Этап 2) — физически невозможно

## 📝 План R2 — требуемые корректировки

| Этап | Что в плане | Что по факту железа |
|------|-------------|---------------------|
| Этап 1 | Qwen2.5-VL 7B | ⚠️ Заменить на **qwen2.5:3b-instruct-q4_K_M** (помещается в VRAM) |
| Этап 2 | Model Router + Консенсус 3 моделей | ⚠️ Консенсус невозможен на 4GB. Router может **переключать** модели (не одновременно). Лимит: 1 модель в VRAM единовременно. |
| Этап 2 | GLM-4 9B expert mode | ❌ Не влезет. Заменить на **deepseek-r1:1.5b** для reasoning |
| Этап 3 | Backtest + Replay | ✅ Не зависит от VRAM (бэктест на CPU/исторических данных) |

## 🛠 Практические шаги (для оператора)

1. **Проверить, что Ollama установлена:**
   ```bash
   ollama --version
   ```

2. **Скачать рекомендованную модель:**
   ```bash
   ollama pull qwen2.5:3b-instruct-q4_K_M
   ```

3. **Обновить конфиг v2.1 backend** (`backend/app/core/config.py`):
   ```python
   OLLAMA_DEFAULT_MODEL = "qwen2.5:3b-instruct-q4_K_M"  # вместо qwen2.5-vl-7b-instruct
   ```

4. **Проверить скорость:**
   ```bash
   curl -X POST http://localhost:11434/api/generate -d '{
     "model": "qwen2.5:3b-instruct-q4_K_M",
     "prompt": "Analyze BTC/USDT 1h. Give JSON: signal, confidence, reasons",
     "stream": false
   }'
   ```
   Цель: <10 сек (метрика Этапа 1).

5. **Для Model Router (Этап 2):** держать `llama3.2:1b` для fast-сигналов, переключать на 3B/7B по необходимости.

---

## ⚠️ Важное уточнение по Qwen2.5-VL

Текущая конфигурация (`qwen2.5-vl-7b-instruct`) — vision-language модель. Для трейдинг-сигналов **vision не нужен**:
- Биржа отдаёт OHLCV как JSON/числа
- Графики анализируются числовыми индикаторами (RSI, MACD, ZigZag)
- Vision-функциональность добавляет вес (~1 GB поверх текста) без пользы для проекта

**Рекомендация:** заменить на text-only Qwen2.5 3B или 7B. Это снимет оффлоад в RAM и ускорит ответ.
